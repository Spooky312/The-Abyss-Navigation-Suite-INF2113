\section{Purpose of This Document}
This document records the requirements analysis performed on the Project
Specification (PS) using the BCIC method (Breakdown, Clarify, Interpret, Categorize).
The goal is to conduct regulated-revision: identify incongruities, clarify intent, revise
requirements into clear/testable statements, and organize them into a consistent structure.

\section{Inputs and Scope}
\begin{itemize}
  \item Analysed Inputs: PS vVERSION, tender notes, requirements tree, selected models.
  \item In-scope: requirement clarity, testability, consistency, completeness gaps.
  \item Out-of-scope: proposing implementation/design solutions beyond requirement intent.
\end{itemize}

\section{Method Used: BCIC}
\begin{itemize}
  \item \textbf{Breakdown}: Identify incongruent requirements (ambiguous, non-testable, missing info, contradictions, compound).
  \item \textbf{Clarify}: Determine the intended meaning/scope using stakeholder info, PS context, assumptions, and notes.
  \item \textbf{Interpret}: Rewrite into clear, atomic, testable requirements using imperative wording (shall/must).
  \item \textbf{Categorize}: Place revised requirements into the correct section/level (Biz Ops vs IT, L0/L1/L2, precedence).
\end{itemize}

\section{BCIC Worked Example (One Full Item)}
\subsection*{Example Item: ISSUE\_ID\_OR\_REQ\_ID}

\textbf{Original PS Statement (as written):}\\
\textit{``The system should monitor vessel health.''}

\vspace{0.5em}
\textbf{Breakdown (what is wrong):}
\begin{itemize}
  \item Ambiguous term: ``monitor'' (continuous vs periodic?).
  \item Scope unclear: what counts as ``vessel health''?
  \item Not fully testable without specifying what must be monitored.
\end{itemize}

\textbf{Clarify (intended meaning / assumptions used):}
\begin{itemize}
  \item Monitoring is expected during mission execution to support safety-first operations.
  \item Vessel health refers to critical subsystems such as hull integrity, propulsion, and power systems.
\end{itemize}

\textbf{Interpret (revised requirement(s), clearer + testable):}
\begin{itemize}
  \item \textbf{R-NEW-01:} The system \textbf{shall continuously monitor} vessel health during mission execution.
  \item \textbf{R-NEW-02:} Vessel health monitoring \textbf{shall include} hull integrity, propulsion status, and power system status.
\end{itemize}

\textbf{Categorize (where it belongs and why):}
\begin{itemize}
  \item Category: IT / Technical (because it is a system capability).
  \item Level: L1 (capability) + L2 (details of what is included).
  \item Precedence: Essential (supports safety and mission continuity).
\end{itemize}
